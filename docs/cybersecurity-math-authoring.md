# Authoring Matematika Cybersecurity

## Sumber dan batas publikasi

Blueprint ada di [kurikulum](../curriculum/cybersecurity-math/README.md), kontrak produk di [desain](superpowers/specs/2026-11-07-cybersecurity-math-design.md), dan urutan kerja di [backlog](cybersecurity-math-tasks.md). Seluruh L0/L1 dan L2M01 sudah authored: 27 lesson, sembilan modul dengan 2 × 5 soal dan task/rubrik masing-masing, serta assessment L0 2 × 13 dan L1 2 × 15 soal. Sebanyak 93 lesson berikutnya tetap draft.

`src/content/cybersecurity-math/catalog.ts` adalah metadata bilingual seluruh target; `foundation.ts`, `fractions.ts`, `measurements.ts`, `numeracy.ts`, `algebra.ts`, `functions.ts`, `growth.ts`, `logarithms.ts` dan `representations.ts` masing-masing memuat tiga lesson lengkap dan dua set soal modul. `l0-assessment.ts` dan `l1-assessment.ts` memuat dua set per level terpisah; `types.ts` mendefinisikan kontrak konten. Publikasi diturunkan dari keberadaan konten lengkap, bukan flag yang diisi untuk stub. Karena itu, jangan memasukkan objek konten parsial ke map authored. Route `[lessonId]` hanya menghasilkan static params untuk konten terbit dan menolak draft/ID tidak dikenal.

`Copy` menyimpan pasangan teks `{ id, en }` yang dipilih dengan preferensi `useLocale` yang sama dengan aplikasi. UI menggunakan pasangan bilingual langsung; satu label menu memakai kamus `messages.ts`. Penggantian locale tidak mengganti ID atau isi angka contoh. Saat menerjemahkan, pertahankan angka, set soal, urutan pilihan, asumsi, dan makna feedback.

## Kontrak lesson saat ini

Setiap `MathLessonContent` memiliki hook, objective, prediction, exploration, explanation, worked steps/result, tiga practice (dua variasi + edge), tiga hint, transfer, reflection, serta dua set checkpoint berisi tiga soal. Setiap `MathQuestion` memiliki jawaban angka atau pasangan pecahan, solusi, feedback salah umum, optional feedback untuk nilai salah tertentu, dan optional penanda critical. Desimal hanya diterima bila `decimalPlaces` ditetapkan; tampilan menjelaskan toleransi setengah unit digit terakhir.

Visual yang sudah tersedia: `count` (dua kelompok dijumlahkan), `groups` (kelompok sama besar), `division` (hasil bagi/sisa), `fraction` (bagian sama besar per utuh), dan `percentage-change` (poin serta perubahan relatif). Setiap aktivitas menentukan initial, target, instruksi aksi, dan soal pengamatan. Pengguna harus mencapai target dan menjawab pengamatan dengan benar. Mengubah input membatalkan jawaban pengamatan aktif. Instruksi eksplorasi tambahan harus dilakukan sebelum kembali ke target, bukan setelah jawaban wajib. Tidak membuat jenis visual universal; tambahkan bentuk yang sesuai ketika modul baru memerlukannya.

Rentang visual bersama berada di `mathVisualBounds`: count/groups 0–8; division total 0–24 dan divisor 1–8; fraction bagian terpilih 0–8 dan penyebut 1–8; perubahan rate awal/akhir 0–100. Baseline nol menampilkan relatif tidak terdefinisi. Desimal visual dibulatkan sampai 4 angka, persen 2 angka; tanda ≈ dan penjelasan membedakannya dari nilai eksak.

Jawaban numerik dibatasi ±1.000.000; integer tetap integer, desimal koma/titik maksimal 4 angka di belakang separator dan tanpa pemisah ribuan/ekspresi. Jawaban pecahan disimpan sebagai `{numerator, denominator}`, numerator integer ±10.000 dan denominator integer 1–10.000; perkalian silang maksimal 100.000.000 tetap exact safe integer. Parser restore memakai batas yang sama. Kolom kosong, denominator nol, NaN/Infinity dan ekspresi ditolak. Soal bertanda negatif memakai keyboard teks agar minus tersedia di ponsel. Belum ada parser ekspresi atau bigint.

L0M03 menambahkan jenis `ratio`, `rate`, dan `bytes`, dirender komponen khusus `MathMeasurementVisual`. Bounds ratio: 1–8 akun dan 0–24 catatan awal; rate: 0–100 kejadian/detik dan 0–2.000 target; bytes: jumlah 0–8, unit index B/kB/KiB 0–2. Select unit menyimpan index tervalidasi. Target nol tidak perlu pemrosesan; rate nol dengan target positif tidak memiliki waktu penyelesaian dalam model. Tabel/hasil live menyebut satuan, pembulatan dan batas hipotesis. Konversi unit mengikuti [referensi NIST tentang binary prefixes](https://physics.nist.gov/cuu/Units/binary.html), ditinjau 7 November 2026; tidak menggunakan angka throughput nyata.

L0M04 menggunakan `distance` (dua posisi −10…10, slider keyboard dan SVG dengan tabel setara), `rounding` (jumlah 0…2.000, unit 10/100/1.000) dan `powers` (basis/eksponen bulat 0…10). Posisi signed divalidasi sesuai bounds, bukan aturan nonnegatif umum. Pembulatan ini hanya untuk nonnegatif dengan halfway naik. Pangkat maksimal 10^10 masih safe integer; pertanyaan yang meminta jawaban tetap harus memenuhi batas grader ±1.000.000. 0^0 dikecualikan dan tidak dihitung; nilai − atau pecahan pada eksponen belum diajarkan.

L1M01 menggunakan `count` dengan optional `inputLabels` bilingual untuk memberi arti x dan tambahan pada model konkret. Visual `budget` membatasi x 0…60 dan anggaran 0…200 dengan biaya 40+3x yang sengaja tetap untuk contoh yang sedang diajarkan. Maksimum dihitung hanya bila anggaran cukup membayar biaya tetap; di bawahnya tidak ada x≥0 yang layak. Tabel membandingkan x dan x+1 tanpa mengklaim biaya/kapasitas nyata. Parameterisasi biaya baru diperlukan saat lesson lain benar-benar memakai model berbeda. Jangan menambahkan parser ekspresi umum untuk menyelesaikan soal yang jawabannya authored.

L1M02 menambahkan `function` (input dan anggota terbesar domain 0…4), `linear` (waktu 0…6 menit utuh dan rate 0…4 catatan/menit), serta `composition` (input 0…6 dan index urutan 0…1), semuanya dirender `MathFunctionVisual`. Model f(x)=2x menampilkan domain {0,…,b} dan range; a>b ditandai tidak didefinisikan, tanpa output nol. Grafik N(t)=3+mt memiliki skala tetap, unit, titik pilihan dan tabel seluruh sampel. Garis putus-putus hanya penghubung sampel, bukan pengukuran/input kontinu. Komposisi f(x)=x+2 dan g(u)=3u berlaku pada integer nonnegatif; kontrol hanya sampel domain. Tabel memuat nilai antara, kedua urutan, langkah invers/domain invers dan reciprocal terpisah. Tidak ada parser fungsi atau perubahan bentuk record.

L1M03 memakai ulang `powers` untuk aturan faktor dan menambah `MathGrowthVisual`: `growth` dengan putaran 0…6 serta tambahan/faktor 2…3, dan `search-space` dengan banyak simbol 1…4 serta panjang 0…6. Grafik 1+bn vs b^n memakai kotak/garis putus-putus dan lingkaran/garis utuh, sumbu salinan/putaran serta tabel semua sampel. Skala y 0…80 atau 0…800 dinyatakan saat b berubah. Pohon menampilkan maksimal dua posisi prefix; tabel mengalikan banyak prefix dengan a^(panjang−panjangPrefix), termasuk satu ε saat panjang nol. Maksimum 4^6=4096; tidak merender seluruh ruang. Hitungan membutuhkan semua kombinasi/pengulangan sah; pemilihan seragam/independen adalah syarat tambahan untuk peluang sama.

L1M04 menambah `MathLogarithmVisual`: `logarithm` basis 2…4/eksponen 0…6 memberi tabel pangkat dan invers eksak; batas kontrol bukan seluruh domain log riil. `binary-choices` k/h 0…8 menampilkan 2^(k−h) hanya bila h≤k; di atasnya tidak ada hasil, bukan kandidat pecahan. Pembelahan seimbang dibedakan dari gagal mencocokkan satu kandidat (tersisa N−1). `search-cost` N 1…256 dan r 0…16, mean (N+1)/2 serta worst N. Rate nol tidak dibagi; waktu dibulatkan sampai empat desimal dengan ≈ bila perlu. Semua asumsi target seragam/pasti di daftar, urutan tetap/tanpa pengulangan dan rate konstan/tanpa overhead-paralelisme tampil. Level L1 memakai grader/snapshot yang sama tanpa perubahan field/versi.

L2M01 menambah `MathRepresentationVisual` dengan tiga jenis: `binary` dan `hexadecimal` menyimpan dua kelompok empat bit (masing-masing 0…15); `signed-byte` menyimpan raw byte 0…255 dan tambahan nonnegatif 0…15. Delapan tombol bit memakai bobot/posisi, `aria-pressed`, keyboard native dan tabel setara. Toggle menghitung nilai baru dengan bobot, tanpa membutuhkan operator bitwise yang baru diajarkan pada modul berikutnya. Biner/hex mempertahankan delapan bit dan nol awal; hex mengelompokkan empat bit per digit. Signed memakai bobot −128, raw≥128 dibaca raw−256; model simpan rawSum%256 memisahkan kedua jumlah matematika, pola simpan, interpretasi dan flag overflow. Seluruh hasil berubah diumumkan live; tidak menganggap semua bahasa/API memakai wrap.

## Progres dan penilaian

`src/lib/cybersecurity-math.ts` mengelola parser, angka, mastery dan prasyarat; `cybersecurity-math-progress.ts` menangani browser storage. Seluruh write matematika hanya menuju `taalmo.cybersecurity-math.progress.v1`. Record memakai `id@contentVersion`; versi publikasi pertama `1.0.0`. Jangan mengubah key/ID database untuk mendukung materi matematika.

Lesson resmi berurutan; modul berikutnya memerlukan checkpoint modul sebelumnya. Modul pertama pada level baru memerlukan `mathLevelPassed` level sebelumnya. Katalog hanya menambahkan checks level bila seluruh materi dan soal assessment lengkap. `MathLevelAssessment` merender ID level yang terdaftar dan mengunci jawabannya sampai seluruh modul lulus. ≥85% dihitung dari nilai aktual, bukan tampilan persen yang dibulatkan, dan semua critical serta jawaban wajib. L0 memiliki 13 soal per set: satu per lesson plus pembanding tambahan per akun vs total; L1 memiliki 15 soal per set yang mencakup 12 lesson ditambah distribusi, worst/mean dan domain log; L2–L9 belum memiliki assessment. Grader modul memeriksa prasyarat sekali dan membaca bukti setiap lesson langsung; modul terakhir membuktikan rantai modul linear sebelumnya tanpa evaluasi berulang secara eksponensial. Parser menerima ID lesson/modul/level ber-versi; snapshot/history lama dan database storage tetap terpisah. Teori published dapat dipreview tanpa menulis progres; setelah unlock, jawaban preview tidak dipromosikan menjadi kelulusan.

Mastery dihitung ulang dari jawaban yang sesuai konten, target eksplorasi, latihan, refleksi terisi, set checkpoint yang telah dilihat, dan timestamp completion. Catatan transfer opsional. Record passed disimpan sebagai snapshot dan tidak ditimpa retake. Parser menolak snapshot yang tidak lagi memenuhi aturan jawaban atau flag bukti yang bertipe salah. Kelulusan hanya untuk versi konten yang aktif; record versi terdahulu disimpan sebagai JSON pasif di `history`, tanpa menyaring jawaban memakai soal versi baru dan tanpa menyetarakannya dengan mastery aktif.

Solusi checkpoint yang dibuka memblokir tombol finish untuk attempt itu; pilih set lain untuk melanjutkan. Membuka hint ketiga/solusi latihan juga berpindah ke set checkpoint lain dan menghapus jawaban checkpoint aktif, tanpa menghapus latihan/refleksi. Retake mempertahankan riwayat bantuan dan menandai set yang benar-benar pernah dilihat; restart sebelum melihat checkpoint tidak menandainya sebagai telah dilihat. Setelah dua set pernah dilihat, latihan tetap bisa memberi progres formatif; tidak diklaim sebagai assessment independen atau terproteksi.

Catatan transfer/refleksi maksimal 6.000 karakter masing-masing. Draf task modul maksimal 20.000, dapat ditulis setelah checkpoint modul; perubahan draf mengembalikan status dari siap direview menjadi draf. Nilai rubrik/review manusia tidak dihasilkan otomatis. Task dan proof tidak mengunci progres lesson.

Resume menyimpan step terakhir melalui interaksi atau tombol navigasi; input angka yang belum diperiksa tidak disimpan sebagai jawaban. Write terbaru memakai ulang records dari storage yang ada, tetapi dua tab yang menulis bersamaan masih dapat saling menimpa. Write gagal memakai memory fallback dan pemberitahuan; mencoba perubahan baru sesudah storage diaktifkan akan mencoba save lagi.

## Review tiap modul

1. Telusuri semua judul/ID/prasyarat dan route; pastikan draft tidak punya link peluncuran.
2. Baca derivasi hasil, unit, asumsi, edge case, dan feedback per miskonsepsi dalam kedua bahasa.
3. Baca grader/parser/write path, invalidasi jawaban, assistance, snapshot retake, dan locked preview.
4. Baca kontrol keyboard/label, alternatif tabel/teks, tema, wrapping navigasi, dan bounds.
5. Perbarui jumlah terbit/rencana, README, roadmap, backlog, dan evidence; commit modul lengkap lalu push.

Ini source/diff review. Jangan membuat unit test, menjalankan test, browser/manual check, lint, typecheck, build, audit script, atau mengeksekusi contoh tanpa permintaan eksplisit pengguna. Jangan menyebut source review sebagai hasil runtime atau jaminan aksesibilitas/perhitungan yang telah dieksekusi.
